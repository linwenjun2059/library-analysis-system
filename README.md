## 📋 项目简介

本项目是一个基于大数据技术栈的高校图书馆借阅行为分析系统，采用**分层数据仓库架构**（ODS→DWD→DWS→ADS），通过**Hive**进行数据存储与管理，**Spark**进行数据处理与分析，实现了从原始数据到业务应用的完整数据链路。系统提供多角色权限管理，支持统计分析、个性化推荐、数据挖掘和预测分析等功能。

### ✨ 核心特性

- 🏗️ **分层数据仓库架构**：ODS原始数据层 → DWD明细数据层 → DWS汇总数据层 → ADS应用数据层
- 📊 **多维度统计分析**：热门图书、活跃用户、院系偏好、借阅趋势、时间分布等
- 🤖 **智能推荐系统**：基于ALS协同过滤、内容过滤和热门推荐的混合推荐算法
- 🔍 **数据挖掘分析**：FPGrowth关联规则挖掘、K-means用户聚类分析
- 📈 **预测分析模型**：逾期风险预测、借阅趋势预测、图书热度预测
- 👥 **多角色权限管理**：高级管理员、图书管理员、普通用户三级权限体系
- 📱 **现代化前端界面**：基于Vue 3 + Element Plus的响应式设计
- 🔄 **完整数据链路**：从CSV原始数据到HDFS，经过Spark处理，最终导出到MySQL供业务系统使用

### 安装步骤

#### 1. 环境准备

确保以下服务正常运行：

```bash
# 检查Hadoop集群
hdfs dfsadmin -report
yarn node -list

# 检查Hive Metastore
jps | grep HiveMetaStore
hive -e "SHOW DATABASES"

# 检查Spark
spark-submit --version
```

#### 2. 初始化MySQL数据库

```bash
mysql -uroot -p < bigdata/mysql/init_mysql.sql
mysql -uroot -p library_analysis -e "SHOW TABLES;"
# 预期输出：31张表
```

#### 3. 准备数据文件

将CSV数据文件上传到Hadoop集群：
（原始数据为逗号分隔CSV，Spark脚本按逗号分隔读取）

```bash
# 上传到HDFS
hdfs dfs -put data/LENDHIST2019_2020.csv /data/library/raw/
```

#### 4. 安装Python依赖

```bash
pip3 install -r bigdata/spark/requirements.txt
```

#### 5. 执行数据链路

```bash
cd deploy
bash run.sh
```

数据链路包含以下步骤：
1. 上传原始数据到HDFS
2. 创建Hive表结构（ODS/DWD/DWS/ADS）
3. 数据清洗（ODS → DWD）
4. 数据汇总（DWD → DWS）
5. 数据分析（DWS → ADS）
6. 导出MySQL（Hive → MySQL）
7. 推荐算法（可选）- 执行 `05_book_recommend.py`
8. 高级数据挖掘（可选）- 执行 `06_advanced_analysis.py`（FPGrowth关联规则 + K-means用户聚类）
9. 预测模型（可选）- 执行 `07_prediction_models.py`

#### 6. 启动后端服务

```bash
cd backend
mvn clean package
java -jar target/library-analysis-system-1.0.0.jar
```

后端服务启动后：
- API地址：http://localhost:8080/api
- Swagger文档：http://localhost:8080/api/swagger-ui/index.html
- Druid监控：http://localhost:8080/api/druid/index.html

#### 7. 启动前端服务

```bash
cd frontend
npm install
npm run dev
```

前端服务启动后访问：http://localhost:3000

### 验证部署

```bash
cd deploy
bash verify.sh
```

## 👥 用户角色与功能

### 🔴 系统管理员（高级管理员）（userType=1）

**战略决策层**，负责整体运营分析和数据挖掘：

- **运营看板**：整体数据概览、关键指标监控
- **用户画像**：用户行为特征、阅读偏好分析
- **专业阅读**：各专业阅读行为特征分析
- **推荐监控**：推荐算法效果评估
- **馆藏利用**：图书利用率、馆藏分布分析（含位置/主题维度）
- **出版分析**：出版社和出版年份综合分析
- **预测分析**：逾期风险、借阅趋势、图书热度预测
- **图书关联分析**：基于FPGrowth算法的关联规则挖掘
- **用户聚类分析**：基于K-means算法的用户分群

### 🟡 图书管理员（userType=2）

**业务执行层**，负责日常业务管理和统计分析：

- **工作台**：业务数据概览
- **借阅记录查询**：借阅记录查询与管理
- **逾期情况分析**：逾期数据统计分析
- **活跃用户分析**：TOP100活跃用户
- **图书排行与分析**：多维度图书排行榜
- **图书详情分析**：单本图书借阅分析
- **时间与续借分析**：借阅时间分布和续借行为分析

### 🟢 普通用户（userType=3）

**学生/教师**，查看个人数据和推荐：

- **个人中心**：个人借阅数据概览
- **借阅记录**：历史借阅记录查询
- **图书推荐**：个性化推荐图书
- **我的阅读画像**：个人阅读特征分析
- **我的排名**：在全校/院系中的排名
- **借阅日历**：借阅时间可视化

### 1. 数据仓库建设

- **ODS层**：原始数据存储，直接映射CSV文件结构
- **DWD层**：数据清洗，生成用户、图书维度表和借阅明细事实表
- **DWS层**：数据汇总，按用户、图书、院系、主题、日期维度汇总
- **ADS层**：应用数据，生成14张核心分析表供业务系统使用（高级数据挖掘可选生成关联规则/用户聚类等附加表）

### 2. 统计分析

- **热门图书分析**：TOP100热门图书，支持多维度排序
- **活跃用户分析**：TOP100活跃用户，借阅量统计
- **院系偏好分析**：各院系借阅偏好、主题分布
- **借阅趋势分析**：时间序列趋势、同比环比分析
- **时间分布分析**：按小时、星期、月份分析借阅模式
- **逾期分析**：逾期率统计、逾期用户分析

### 3. 推荐系统

采用**混合推荐算法**，结合三种推荐策略：

- **ALS协同过滤**：基于用户借阅历史的相似度推荐
- **内容过滤**：基于图书主题相似度的推荐
- **热门推荐**：基于借阅热度的推荐
- **混合推荐**：加权融合三种算法，生成个性化推荐列表

### 4. 数据挖掘

- **FPGrowth关联规则**：挖掘图书之间的关联关系（如：借阅A图书的用户也倾向于借阅B图书）
- **K-means用户聚类**：将用户分为不同群体，分析群体特征

### 5. 预测分析

- **逾期风险预测**：基于用户历史行为预测逾期风险
- **借阅趋势预测**：预测未来借阅量趋势
- **图书热度预测**：预测图书未来热度变化
![随机森林逾期风险预测模型结构示意图](images/随机森林逾期风险预测模型结构示意图.png)

### 6. 高级数据挖掘

- **FPGrowth关联规则挖掘**：通过 `06_advanced_analysis.py` 执行，挖掘图书之间的关联关系
![FPGrowth算法FP-Tree构建示例图](images/FPGrowth算法FP-Tree构建示例图.png)
- **K-means用户聚类**：通过 `06_advanced_analysis.py` 执行，将用户分为不同阅读偏好群体

## 🐛 常见问题

### 1. Hive表创建失败

**问题**：执行Hive SQL时提示表已存在

**解决**：
```bash
# 删除旧表
hive -e "DROP TABLE IF EXISTS library_ods.ods_library_lend;"
# 重新执行创建脚本
hive -f bigdata/hive/01_create_ods.sql
```

### 2. Spark任务失败

**问题**：Spark任务执行失败，提示内存不足

**解决**：
- 检查YARN资源分配
- 调整Spark executor内存配置
- 减少数据量或增加集群资源

### 3. MySQL连接失败

**问题**：Spark导出数据到MySQL失败

**解决**：
- 检查MySQL服务是否启动
- 确认MySQL JDBC驱动路径正确
- 检查MySQL用户权限

### 4. 前端API请求失败

**问题**：前端无法访问后端API

**解决**：
- 检查后端服务是否启动
- 确认CORS配置正确
- 检查API地址配置
